## 2026-07-03 — ECC (ecosystem-first, the light-canvas readability reckoning)

- KEPT: the `claude` preset (cream, near-black ink, terracotta accent) as the on-theme fallback when `brand_extract.py` on ecc.tools came back confidence=low -- since the project literally is "Everything Claude Code," the library preset read as earned, not lazy. The RECEIPT framework's sparkline (March-to-now star curve) plus a stack "receipt" card (8 hours, $15,000) carried the origin-story proof-over-hype thesis with zero adjectives.
- KILLED: seven iterations chasing the new (2026-07-02) per-scene readability gate on a LIGHT canvas for the first time -- every prior gate run had been against dark-canvas videos (bright text on black), and the gate's light-polarity branch (p0.7 darkest-pixel check) turned out to punish dark-on-cream type far harder than the symmetric dark-canvas case at the same nominal size, thanks to sRGB anti-aliasing asymmetry. Root-caused via direct pixel sampling at the gate's own 540px scale (not eyeballing renders) and fixed at the renderer: a universal `-webkit-text-stroke` on hero/body text plus larger type for `stack`/`terminal`/`close`/`diagram` (with `terminal` and `diagram` boxes widened first so the bigger type wouldn't clip -- caught by the filmstrip pass, not the numeric gate). Also killed: the accent token itself (`#CC785C`) sat almost exactly on the gate's dark/light luma boundary, making the one intentional inverted (`flash`) beat flicker between polarities run to run -- fixed by deepening the accent to `#8B4226`, unambiguously dark and also better contrast.
- NEXT: the readability gate showed real run-to-run jitter (+/-10 luma points on an unchanged capture) from JPEG-screencast/font-AA variance -- when a scene reads within ~5 points of a threshold, do not ship on one green run; the actual fix needs real margin (this run ended with all 8 scenes at 66-73 baseline, comfortably clear). Any FUTURE light-canvas preset (`gallery`, `editorial-paper`, `editorial-90s`, `geominimal`) should have its scene set run through `screening_room.py` before assuming dark-canvas type sizes transfer -- they do not.

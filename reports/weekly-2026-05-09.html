The All-Star · skills by @mattpocockuk

The Lede

On May 14, 2026, Matt Pocock pushed documentation for a new skill called caveman to his public GitHub repository. That commit pulled +3,392 stars in 24 hours, leading GitHub trending that week for single-day velocity. Pocock didn't announce a product or publish a launch thread. He opened the .claude/ directory he runs Total TypeScript with, named the failure modes each skill fixes, and let the install command be the punchline.

The Build

What it does. skills ships 17 composable Claude Code skill files, installed with one command, npx skills@latest add mattpocock/skills. Each skill addresses one named failure mode in agent-driven development. grill-me sets intent before a session begins. tdd runs the inner development loop. diagnose triages errors without losing context. zoom-out reframes when the agent is stuck. improve-codebase-architecture audits entropy on a longer horizon. caveman strips the agent's output to its essentials. The output of each skill feeds the input of the next. That's a loop, not a list.

Where it came from. Pocock founded Total TypeScript as a course platform and served as devrel for XState. The skills repo began as his private .claude/ directory and accumulated 78 commits across skills including handoff, prototype, review, and writing-fragments before he made it public.

What changed this week. The caveman skill documentation landed on May 14. Within 24 hours the repo went from 80,296 to 84,400 stars. The velocity held through May 15, outpacing every other project on GitHub trending for percentage climb during the window.

The pattern this week

Agents are gaining persistent memory and self-composing skill loops between sessions. hermes-agent (@Teknium) shipped its v0.13.0 Hermes Curator on May 7, a subsystem that distills new skills from completed runs and writes them to disk for reuse. openhuman (@senamakel) runs a continuous background process that re-reads its stored notes between requests, writing everything as Obsidian-compatible markdown on the user's machine. skills (@mattpocockuk) makes the structural bet concrete, 17 Claude Code skill files in .claude/skills/, each feeding the next in a closed loop. The counter signal is react-doctor and proofshot, both of which built their audiences this week on the opposite premise. Agents still can't reliably audit their own output.

The lesson this week · Persist agent skills as composable text files before the next run

Both skills and hermes-agent landed this week with the same architectural instinct. Skills are files, not runtime config.

skills (@mattpocockuk) drops 17 files into .claude/skills/ with one npx command. Each file defines the behavior for one step in the feedback loop. hermes-agent (@Teknium) takes that further. Its v0.13.0 Hermes Curator writes new skills to disk after each completed run, building the agent's capability library over time.

An agent loop that doesn't persist the skills it discovers isn't learning. It's running in place. The skill file is the unit of composition.

# From skills by @mattpocockuk
npx skills@latest add mattpocock/skills
# Installs to .claude/skills/ - versionable, composable, survives restarts

# The composable loop (each step feeds the next)
# grill-me -> tdd -> diagnose -> zoom-out -> improve-codebase-architecture

This pattern applies to agents that run across more than one session. One-shot tasks where state persistence adds overhead without return don't need it.

Reading list

  • Equipping agents for the real world with Agent Skills. The Anthropic Engineering spec (Oct 2025) that defined the SKILL.md format and progressive-disclosure architecture underpinning every composable skill in mattpocock/skills.
  • EvoSkill, a Virginia Tech and Sentient paper on automated skill discovery for multi-agent systems. Shows that agents can synthesize and transfer reusable skills from failure traces, the academic backing for why the skill-accumulation loop in hermes-agent generalizes.
  • State of AI Agent Memory 2026 by mem0.ai. Maps episodic vs semantic storage, temporal queries, and cross-session identity with benchmark data from LoCoMo and LongMemEval, contextualizing the tradeoffs openhuman and hermes-agent are both making.

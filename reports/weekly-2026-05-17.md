## The All-Star · autoresearch by @karpathy

### The Lede

autoresearch by @karpathy crossed 82k stars in 72 hours of going public. By 2026-05-22 it was atop GitHub's Python trending list. The project runs on a single NVIDIA GPU. The loop is tight. One agent edits train.py, trains nanochat for exactly 5 minutes, scores val_bpb, keeps the improvement or reverts to the previous state, then goes again. Twelve experiments per hour. About 100 experiments while you sleep. The protocol, not the model, is the contribution.

### The Build

autoresearch is a closed-loop agent for ML architecture search. The agent modifies train.py directly, runs a 5-minute training session on nanochat, reads the val_bpb metric, and applies a keep-or-revert decision. The 5-minute wall clock is fixed per experiment, which makes cross-architecture comparisons fair by construction. The whole system targets one file on one GPU.

The lineage is visible in the repo list. nanoGPT at 58k stars, llm.c at 30k stars, micrograd and nanochat. Each project keeps the kernel tiny and moves the complexity boundary outward. autoresearch moves it outward again by externalizing the iteration loop entirely.

Since the daily tribute on 2026-05-22, the project crossed 82.8k stars. Community adaptations include a 910-experiment 16-GPU parallelization run by Alex Kim and Romil Bhardwaj using SkyPilot, and a Claude Code skill package by uditgoenka with file-level access controls. @karpathy posted publicly about the next direction.

## The lesson this week. Address by content, not by position

Two of the five finalists converge on the same primitive. oh-my-pi (@_can1357) has the model point at content hashes rather than line numbers. When files shift, the anchor holds. Conflicts surface as hard errors, not silent corruption.

code-review-graph (@tirth_8205) applies the same idea one level up. Instead of giving the agent a file range to read, dependency graph traversal identifies exactly which files a change reaches across 27,732 files. The agent gets structural addresses, not positional ones.

Both systems make incorrect addresses impossible rather than unlikely.

Use this when your agent writes code into a codebase it didn't author. Skip it for open-ended research loops where the objective is fixed and the hypothesis varies freely. autoresearch works precisely because it holds val_bpb constant and lets train.py mutate without addressing constraints.

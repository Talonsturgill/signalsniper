**taste-skill** — "The Anti-Slop Frontend Framework for AI Agents."

## What it actually does (verified against README + site)
- Reads a project brief, infers a design direction, and ships interfaces that don't
  look templated. Includes real design-system mappings, an audit-first protocol for
  redesigns, and strict pre-flight verification before output.
- Three adjustable dials: `DESIGN_VARIANCE`, `MOTION_INTENSITY`, `VISUAL_DENSITY`.
- Sub-skills: `design-taste-frontend` (v2 default), `gpt-taste`, `image-to-code`,
  `redesign-existing-projects`, plus aesthetic variants `brutalist-skill`,
  `minimalist-skill`, `soft-skill`, and image-gen skills.
- Supported agents (8): Cursor, Claude Code, Codex, OpenCode, Gemini CLI, AI Studio,
  v0, Lovable.

## The thesis (in the creator's own words)
From Leon's X post: Claude's stock frontend skill tells the model to "pick an extreme
aesthetic" and "be creative." The problem, he argues, is that LLMs are just based on
probability, so without strict rules they statistically default to the generic mean.
taste-skill replaces "be creative" vibes with explicit, opinionated rules. This is the
different angle the tribute leans on: **taste encoded as constraints, not encouragement.**

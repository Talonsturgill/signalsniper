# This Week in AI · Five Builds, Not One New Model

*Issue 5 · May 31 to June 6, 2026 · ~7 min read*

Five projects made the shortlist this week, and every one of them sits between an agent and something it wants to reach. Karim Shoair's scraper keeps its grip on a page after the HTML moves. Jeremiah Lowin's framework collapses a working MCP server down to a single decorator. Nick Bushak gave each coding agent its own cloud machine to run on. None of them trained anything. ## The All-Star · headroom by @chopra_tejas

On June 1, headroom crossed onto GitHub's daily trending board at the number two slot and gained more than 3,000 stars in a single day. Tejas Chopra didn't ship a new model to do it. He shipped a layer that sits in front of one. The repo is two days past a fresh release and already carries fifteen thousand stars. What it does is plain, and it lands on a problem every agent builder keeps hitting. It cuts the size of everything an agent feeds the model before the model ever sees it.

headroom is a compression layer for the context window. Tool outputs, logs, files, RAG chunks, and chat history all get squeezed before they reach the model. The stated reduction runs 60 to 95 percent. On the project's own benchmarks, a code-search task dropped from 17,765 tokens to 1,408 while GSM8K accuracy held at its 0.870 baseline. What keeps it safe is reversibility. Six compressors feed a local store and the original text stays on disk, so the agent can pull the full version back through a tool call whenever it needs it. Lossy on the wire, lossless on demand.

Chopra is a storage engineer at Netflix who architects petabyte-scale systems, and headroom reads like that instinct aimed at a new scarce resource. He built it to cut his own bills, then opened it. His earlier public work was conference talks and storage infrastructure, not a trending repo.

The last seven days are when it turned. headroom climbed from roughly 11,000 stars to just over 15,000, a v0.23 release landed on June 4 with a GitHub Copilot mode, and a wave of press picked up the Netflix angle. Chopra has said the tool saved its users around 700,000 dollars.

> Remember, a model is no longer a moat!

That's @chopra_tejas in a June post, and the next sentence promised an open model of his own, built for agents. See the [post on X](https://x.com/chopra_tejas/status/2031543876633383055).

## The pattern this week

The leverage moved to the connective tissue around the model, not the model itself. @jlowin's FastMCP pushed out v3.4 on June 2, a release that lets a stdio-only host reach a remote server over HTTP and SSE. @D4Vinci1's Scrapling, now past 61,000 stars, carries its own server so an agent pulls the live web without glue code. headroom does the same trick for context, shrinking the read before it lands. Three teams, three problems, one shared move. The model is fixed, so the value collected at its edges. The counter-case is that this layer isn't settled yet. @nbushak's boxes.dev stays a closed cloud product, and @mvanhorn's last30days ships as a portable skill instead of a server, its star velocity already flattened.

## The lesson this week · Ship the MCP server next to your library, not after it

If you're building a tool for agents in 2026, the integration surface is the product, and right now that surface speaks MCP. The cost of adding one has fallen through the floor. @jlowin's FastMCP turns a typed Python function into a server with one decorator, schema and transport generated for you.

```python
from fastmcp import FastMCP

mcp = FastMCP("Demo")

@mcp.tool
def add(a: int, b: int) -> int:
    """Add two numbers"""
    return a + b

if __name__ == "__main__":
    mcp.run()
```

That's the whole thing. @chopra_tejas shipped headroom as a library, a proxy, and a server on one pipeline, so it drops into a stack three different ways. @D4Vinci1 baked the protocol straight into Scrapling. The move is to plan for the server on day one instead of bolting it on once people ask. The exception is a tool with no agent on the other end. If a person runs it by hand, a clean CLI still beats a protocol you don't need.

## Code from the week

### headroom · one wrap of the message list, with the savings reported back

```python
from headroom import compress

result = compress(messages, model="gpt-4o")
response = client.messages.create(
    model="gpt-4o",
    messages=result.messages,
)
print(f"Saved {result.tokens_saved} tokens ({result.compression_ratio:.0%})")
```
